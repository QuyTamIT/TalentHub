## Purpose and scope

Add an owner-safe, versioned persistence store for the Roadmap-first learner AI feature. The change creates four empty tables and protective indexes, constraints and triggers. It does not alter, backfill, delete or rewrite any existing row or table.

The application retains completed model or explicitly labelled rule-fallback roadmaps, their immutable 30–60–90 day content, and append-only learner task progress. Raw provider requests, raw provider responses, API keys, Authorization headers and raw assessment answers are not persisted.

## Exact schema contract

All UUIDs are `CHAR(36)`. MySQL tables use InnoDB, `utf8mb4`, `utf8mb4_unicode_ci`, UTC `DATETIME(6)` timestamps and `ON DELETE RESTRICT ON UPDATE CASCADE` foreign keys.

### `learner_ai_roadmaps`

- `id CHAR(36) NOT NULL` primary key.
- `studentId CHAR(36) NOT NULL`, FK to `student_profiles.id`.
- `runId CHAR(36) NOT NULL`, unique FK to `learner_recommendation_runs.id`.
- `versionNumber INT UNSIGNED NOT NULL`, check `>= 1`.
- `contractVersion VARCHAR(100) NOT NULL`.
- `status VARCHAR(20) NOT NULL DEFAULT 'active'`, check `active|superseded`.
- `executiveSummary VARCHAR(2000) NOT NULL`.
- `primaryDirectionJson LONGTEXT NOT NULL`, valid JSON.
- `alternativeDirectionsJson LONGTEXT NOT NULL`, valid JSON.
- `insightsJson LONGTEXT NOT NULL`, valid JSON.
- `confidenceBand VARCHAR(20) NOT NULL`, check `low|medium|high`.
- `evidenceSummaryJson LONGTEXT NOT NULL`, valid JSON.
- `providerRequestId VARCHAR(128) NULL`; safe provider-generated identifier only.
- `responseHash CHAR(64) NULL`; lowercase SHA-256 only.
- `generatedAt DATETIME(6) NOT NULL`.
- `supersededAt DATETIME(6) NULL`, consistent with `status`.
- `createdAt DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)`.
- Unique indexes: `uq_learner_ai_roadmaps_student_version (studentId, versionNumber)`, `uq_learner_ai_roadmaps_run (runId)`, and `uq_learner_ai_roadmaps_id_student (id, studentId)`.
- Lookup index: `idx_learner_ai_roadmaps_student_status_generated (studentId, status, generatedAt)`.
- An owner trigger requires `learner_recommendation_runs.studentId = learner_ai_roadmaps.studentId`.
- Generated content is immutable. An update may only change `status` from `active` to `superseded` and set `supersededAt`; deletes and any content rewrite are rejected.

### `learner_ai_roadmap_phases`

- `id CHAR(36) NOT NULL` primary key.
- `roadmapId CHAR(36) NOT NULL`, FK to `learner_ai_roadmaps.id`.
- `position TINYINT UNSIGNED NOT NULL`, check `1..3`.
- `startDay TINYINT UNSIGNED NOT NULL`, `endDay TINYINT UNSIGNED NOT NULL`, exact range check for `(1,0,30)`, `(2,31,60)`, `(3,61,90)`.
- `code VARCHAR(64) NOT NULL`.
- `title VARCHAR(255) NOT NULL`.
- `goal VARCHAR(1000) NOT NULL`.
- `skillFocus VARCHAR(500) NOT NULL`.
- `deliverable VARCHAR(1000) NOT NULL`.
- `effortLabel VARCHAR(255) NOT NULL`.
- `metricLabel VARCHAR(1000) NOT NULL`.
- `evidenceJson LONGTEXT NOT NULL`, valid JSON.
- `createdAt DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)`.
- Unique `uq_learner_ai_roadmap_phases_position (roadmapId, position)` and index `idx_learner_ai_roadmap_phases_roadmap (roadmapId)`.
- Rows are immutable and cannot be updated or deleted.

### `learner_ai_roadmap_tasks`

- `id CHAR(36) NOT NULL` primary key.
- `phaseId CHAR(36) NOT NULL`, FK to `learner_ai_roadmap_phases.id`.
- `position TINYINT UNSIGNED NOT NULL`, check `1..5`.
- `title VARCHAR(255) NOT NULL`.
- `description VARCHAR(1500) NOT NULL`.
- `estimatedMinutes SMALLINT UNSIGNED NOT NULL`, check `5..1440`.
- `actionType VARCHAR(30) NOT NULL`, check `self_task|register_activity`.
- `targetType VARCHAR(30) NULL` and `targetId CHAR(36) NULL`. Both are null for `self_task`; `register_activity` requires `targetType='activity'` and a non-null target UUID.
- `evidenceJson LONGTEXT NOT NULL`, valid JSON.
- `createdAt DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)`.
- Unique `uq_learner_ai_roadmap_tasks_position (phaseId, position)` and index `idx_learner_ai_roadmap_tasks_phase (phaseId)`.
- Rows are immutable and cannot be updated or deleted.

### `learner_ai_roadmap_task_events`

- `id CHAR(36) NOT NULL` primary key.
- `taskId CHAR(36) NOT NULL`, FK to `learner_ai_roadmap_tasks.id`.
- `studentId CHAR(36) NOT NULL`, FK to `student_profiles.id`.
- `status VARCHAR(20) NOT NULL`, check `in_progress|completed|skipped`. Re-entering a skipped task is represented by a later `in_progress` event.
- `requestId VARCHAR(100) NOT NULL`, idempotency identifier generated by the application.
- `occurredAt DATETIME(6) NOT NULL`.
- `createdAt DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)`.
- Unique `uq_learner_ai_roadmap_task_events_request (taskId, requestId)`.
- Indexes `idx_learner_ai_roadmap_task_events_task_occurred (taskId, occurredAt)` and `idx_learner_ai_roadmap_task_events_student_created (studentId, createdAt)`.
- An insert owner trigger traverses task → phase → roadmap and requires the roadmap learner to equal `studentId`.
- Events are append-only; updates and deletes are rejected.

## Lock and capacity expectations

The migration contains `CREATE TABLE`, `CREATE INDEX` and `CREATE TRIGGER` statements for new empty objects only. It performs no `ALTER TABLE`, data copy or backfill. MySQL will briefly acquire metadata locks while resolving referenced parent tables; expected lock duration is seconds. Apply during a low-traffic deployment window with the normal migration lock timeout and stop if lock wait exceeds the database runbook threshold.

Initial row count for every new table must be zero. Storage growth is proportional to generated roadmap versions and append-only task events; no source assessment payload or raw provider body is duplicated.

## Recovery and rollback-by-forward-fix

The application migration is intentionally forward-only. If validation fails before application writes, stop deployment and create a reviewed corrective migration; do not edit the applied migration. If the feature must be disabled after writes, set the AI rollout to disabled/0%, preserve all roadmap rows, and deploy a forward fix. Restore the verified backup only under the database incident runbook. Dropping tables is not an automatic rollback and requires separate destructive-change approval after proving the tables are empty or exporting their data.

## Verification queries

```sql
SELECT DATABASE(), @@session.time_zone;

SELECT TABLE_NAME, ENGINE, TABLE_COLLATION, TABLE_ROWS
FROM information_schema.tables
WHERE TABLE_SCHEMA = DATABASE()
  AND TABLE_NAME IN ('learner_ai_roadmaps','learner_ai_roadmap_phases','learner_ai_roadmap_tasks','learner_ai_roadmap_task_events');

SELECT roadmap.studentId, roadmap.runId
FROM learner_ai_roadmaps AS roadmap
LEFT JOIN learner_recommendation_runs AS run ON run.id = roadmap.runId AND run.studentId = roadmap.studentId
WHERE run.id IS NULL;

SELECT event.id
FROM learner_ai_roadmap_task_events AS event
JOIN learner_ai_roadmap_tasks AS task ON task.id = event.taskId
JOIN learner_ai_roadmap_phases AS phase ON phase.id = task.phaseId
JOIN learner_ai_roadmaps AS roadmap ON roadmap.id = phase.roadmapId
WHERE roadmap.studentId <> event.studentId;
```

Both orphan/owner mismatch queries must return zero rows.
